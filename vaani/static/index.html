    Outcome distribution

    The query behind the view

    SQLite
    SELECT language, source, planner,
       COUNT(*) AS sessions,
       SUM(outcome = 'booked') AS bookings,
       ROUND(100.0 * SUM(outcome = 'booked')
             / COUNT(*), 1) AS booking_pct
FROM sessions
GROUP BY language, source, planner;

    THE PROJECT, EXPLAINED

    A small system. Real trade-offs.

    Vaani is a portfolio project for bilingual voice-agent design and evaluation.

    Why this project?

    The SquadStack role emphasizes conversation design, Python, SQL, prompt engineering, English/Hindi communication, and structured evaluation. This project connects each requirement to something you can demonstrate.

    What you own

    The qualification policy, bilingual responses, structured intent contract, booking transaction, regression scenarios, SQL reporting, and this local lab.

    What you reuse

    The optional voice adapter follows LiveKit’s Python starter and pipeline hooks. LiveKit handles audio transport; Sarvam supplies STT/TTS. Attribution is recorded in THIRD_PARTY.md.

    Conversation architecture

    Customer text / transcribed speech↓Rules baseline / Gemini intent extraction↓Validated decision + Python state machine↓SQLite transaction + approved response↓Transcript, outcomes, evaluation evidence

    Honest boundaries

    Voice Studio connects to LiveKit when configured. The offline baseline is a limited rules parser, not an LLM. Gemini needs your own credentials. Prompt variants affect Gemini only. The voice adapter needs optional dependencies and credentials and must be tested with real audio.

    No actual calls, CRM updates, or dealership bookings occur. The local app has no multi-user authentication and binds to localhost. Do not expose it as a production service.

    A useful interview demo

    1. Qualify a lead in Hindi and confirm a demo slot.
    2. Ask for an unapproved discount and inspect the reply.
    3. Retry a confirmation: the reservation stays unique.
    4. Run the evaluation suite and open a transcript.
    5. Explain the SQL denominator and why simulated results are limited.
